# TutorSite

TutorSite - веб-платформа на Django для взаимодействия учеников и репетиторов: поиск преподавателей, профильные анкеты, чат, заявка на обучение, расписание занятий, группы и уведомления.

## Текущий статус проекта
Проект находится в стадии активной разработки.

Что уже реализовано:
- кастомная модель пользователя (`CustomUser`);
- каталог репетиторов с фильтрами;
- карточка репетитора с отзывами и рейтингом;
- регистрация/логин/личный кабинет;
- личный чат ученик <-> репетитор;
- заявка на обучение через чат + принятие заявки репетитором;
- привязка ученика к репетитору (`TutorStudentLink`);
- панель репетитора (группы, уроки, редактирование/удаление уроков);
- уведомления ученикам при создании/изменении/удалении уроков;
- светлая/темная тема интерфейса.

## Основной функционал
### Для ученика
- регистрация и авторизация;
- поиск репетитора по ключевым словам, предмету, городу, цене и опыту;
- просмотр детальной анкеты репетитора;
- отправка сообщений в чат;
- отправка заявки на обучение;
- просмотр расписания в личном кабинете и календаре;
- получение уведомлений об уроках;
- оставление отзывов и оценок.

### Для репетитора
- создание анкеты репетитора;
- редактирование анкеты;
- прием заявки ученика из чата;
- управление прикрепленными учениками;
- создание групп;
- назначение, редактирование и удаление занятий;
- автоматическая рассылка уведомлений ученикам при изменениях уроков.

## Архитектура приложений
### `users`
Отвечает за:
- кастомную модель пользователя;
- регистрацию и вход;
- личный кабинет;
- уведомления;
- счетчики непрочитанных сообщений/уведомлений в шапке.

### `tutors`
Отвечает за:
- предметы (`Subject`);
- профиль репетитора (`TutorProfile`);
- связь репетитор-ученик (`TutorStudentLink`);
- группы учеников (`StudentGroup`);
- отзывы (`Review`) и рейтинг.

### `lessons`
Отвечает за:
- модель занятия (`Lesson`);
- панель управления репетитора;
- создание и редактирование уроков;
- создание групп;
- отправку системных уведомлений ученикам при изменении уроков.

### `chat`
Отвечает за:
- диалоги (`Conversation`);
- сообщения (`Message`);
- заявку на обучение (`kind='enrollment_request'`) и ее подтверждение.

### `core`
Отвечает за:
- главную страницу сайта.

### `payments` и `reviews`
- присутствуют в проекте, но в текущей версии функционал практически не реализован;
- `reviews` пока не подключен в корневых URL, т.к. отзывы сейчас работают через приложение `tutors`.

## Модели данных
### users
- `CustomUser(AbstractUser)`
- поля: `is_tutor`, `is_student`, `avatar`
- `Notification`: уведомления пользователя (`kind`, `title`, `body`, `link`, `is_read`, `created_at`)

### tutors
- `Subject`: предмет (`name`, `slug`)
- `TutorProfile`: анкета репетитора (`user`, `avatar`, `bio`, `experience_years`, `subjects`, `hourly_rate`, `city`)
- `TutorStudentLink`: связь репетитор <-> ученик (уникальная пара)
- `StudentGroup`: группа учеников у конкретного репетитора
- `Review`: отзыв ученика о репетиторе (`rating` 1..5, `text`)

### lessons
- `Lesson`: урок с привязкой к репетитору и либо к одному ученику, либо к группе
- есть DB-ограничение `lesson_has_exactly_one_target`: одновременно должен быть выбран только один тип цели (`student` или `group`)

### chat
- `Conversation`: уникальный чат пары ученик <-> репетитор
- `Message`: сообщение с типом `text` или `enrollment_request`, статус заявки (`pending/accepted/declined`), флаг прочитанности

## Маршруты URL
### Корневые подключения (`tutorsite/urls.py`)
- `/admin/`
- `/` -> `core`
- `/accounts/` -> `users`
- `/tutors/` -> `tutors`
- `/lessons/` -> `lessons`
- `/chat/` -> `chat`

### `users`
- `/accounts/register/` - регистрация ученика
- `/accounts/login/` - вход
- `/accounts/logout/` - выход
- `/accounts/profile/` - личный кабинет
- `/accounts/cabinet/` - алиас личного кабинета
- `/accounts/notifications/` - список уведомлений

### `tutors`
- `/tutors/` - каталог репетиторов
- `/tutors/<id>/` - детальная страница репетитора
- `/tutors/become/` - создать анкету репетитора
- `/tutors/edit/` - редактировать анкету репетитора

### `lessons`
- `/lessons/tutor/` - панель управления репетитора
- `/lessons/tutor/lesson/<id>/edit/` - редактирование занятия
- `/lessons/tutor/lesson/<id>/delete/` - удаление занятия

### `chat`
- `/chat/` - список диалогов
- `/chat/start/<tutor_id>/` - старт/переход в чат с репетитором
- `/chat/<id>/` - детальный диалог

## Роли и права доступа
- Гость:
  - просмотр главной и каталога;
  - просмотр анкеты репетитора;
  - не может писать в чат, оставлять отзывы, управлять уроками.

- Авторизованный ученик:
  - чат с репетитором;
  - заявка на обучение;
  - просмотр кабинета, расписания и уведомлений;
  - может оставить отзыв.

- Репетитор (`is_tutor=True` + `TutorProfile`):
  - все права ученика;
  - доступ к панели управления уроками;
  - создание групп и занятий;
  - принятие заявок на обучение.

## Установка и запуск
### 1) Клонирование
```bash
git clone <repo_url>
cd Tutorsite
```

### 2) Создание и активация виртуального окружения
Linux/macOS:
```bash
python -m venv venv
source venv/bin/activate
```

Windows (PowerShell):
```powershell
python -m venv venv
venv\Scripts\Activate.ps1
```

### 3) Установка зависимостей
В репозитории сейчас нет `requirements.txt`, поэтому минимум:
```bash
pip install Django Pillow
```

### 4) Миграции
```bash
python manage.py migrate
```

### 5) Создание суперпользователя (опционально)
```bash
python manage.py createsuperuser
```

### 6) Запуск dev-сервера
```bash
python manage.py runserver
```

Открыть в браузере: `http://127.0.0.1:8000/`

### Проверка проекта
```bash
python manage.py check
```

## Статические и медиа-файлы
- Статика:
  - `STATIC_URL = 'static/'`
  - `STATICFILES_DIRS = [BASE_DIR / 'static']`
- Медиа:
  - `MEDIA_URL = '/media/'`
  - `MEDIA_ROOT = BASE_DIR / 'media'`
- В режиме `DEBUG=True` медиа раздаются через `urlpatterns += static(...)`.

## Админ-панель
После создания суперпользователя:
- перейти на `/admin/`;
- доступны модели `CustomUser`, `Notification`, `Subject`, `TutorProfile`, `Review`, `TutorStudentLink`, `StudentGroup`, `Lesson`, `Conversation`, `Message`.

## Известные ограничения
- Нет `requirements.txt`/`pyproject.toml` с зафиксированными версиями зависимостей.
- Приложение `payments` пока не реализовано по бизнес-логике.
- Приложение `reviews` присутствует как заготовка, но фактическая логика отзывов находится в `tutors`.
- Поле `ALLOWED_HOSTS` пустое (подходит только для локальной разработки).
- `SECRET_KEY` хранится в `settings.py` (для production нужно вынести в переменные окружения).
- Тесты в большинстве приложений пока отсутствуют.
